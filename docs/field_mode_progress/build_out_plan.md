# Field Mode — Non-Phone Build-Out (Agent Waves)

## Context

`docs/field_mode_phone_mesh_plan.md` + `docs/field_mode_test_strategy.md` describe the Field Mode phone-mesh system. Phase 1 (real-phone chirp sync) still gates the phone app, but a large share of the plan needs no phones: the **Server track (S)**, most of **Phase 2** (shared `minimappr-core`, solver/tracker ports, sync/layout math, clip codec, message enum, BirdNET+ V3.0 migration), the **Layer 1 acoustic simulator** and **Layer 2 seeded mesh simulator**, and buildable-but-unproven shells (Cloudflare relay, WASM PWA, Android KMP skeleton). This plan front-loads all of that, tested locally or on the Bluefin box, so Phase 1 hardware time is spent only on what truly needs phones — and the simulator pre-answers Phase 1's band/FM/slot questions.

User decisions: all four scopes included; xeno-canto CC calls + Bluefin snippets for audio fixtures; integration branch `field-mode`, with ready pieces promoted to `main` after an Opus reviewer subagent reviews and improves them; orchestrated as Agent-tool waves (not Workflow).

Key facts from survey:
- No Cargo workspace. Sidecar (`minimappr-ingest-sidecar/`, ~21.8k lines, ~183 tests) is one binary crate. Cleanly movable to a no-tokio lib: `dsp_math.rs`, `gcc_phat.rs`, `range_projection.rs`, `srp_phat.rs` (+ `PairTdoa` from `dsp_worker.rs:164`), `butter_*_sos` (`dsp_worker.rs:2476/2506`), `dsp.rs` `SensorStreamBuffer` (only `tracing`), `audio_payload.rs`. `SIRITH_MIC_POSITIONS_M` at `dsp_worker.rs:41`. Python↔Rust parity runs via subprocess oracle modes (`main.rs:439-695`: `srp-oracle`, `preprocess-oracle`, …). No nalgebra, LM, FLAC, PyO3.
- **No ground-truth bundles exist** (`tests/data/calibration/` has only a README; replay test skips). Server-track gates must run on **simulated bundles**; Bluefin snippets (≈11 GB, mono-ish, ~45% frame drops) score only duplicates/label stability.
- `replay.py` scoring (`evaluate_bundle` :303) is per-event, no track/entity concept; `bundle.py` allows one label + one static point per event.
- Tracking: single overwritten label per track (`tracking.py:376-389`), fingerprints EMA at :111 (natural home for log-odds); filters chosen at `tracking.py:158-194`; omni detections never reach the tracker (`assembly.py:327-347`). `ReportingFusionPolicy` (`reporting_fusion.py`) uses fixed buckets.
- BirdNET v2.4 TFLite (`classifiers/birdnet.py`, single `min_confidence` dropping at :683). `onnxruntime` already a dependency (`pyproject.toml:43`).
- New config keys touch: `config.py` field + env loader + sub-config, `settings_store.py:185`, `main.py:3119`, `core/config_groups.py`, `core/pipeline_graph.py` (AGENTS.md §2.5; enforced by `tests/test_config_structured.py`).

## Ground rules (in every agent brief)

- Read the two field-mode docs + AGENTS.md first. Files < 500 lines, no magic numbers (config), hyper-descriptive names, no absolute level gates (faint birds), no audio to disk before classification, no hot-path blocking.
- Every server behaviour change ships **behind a config flag defaulting to current behaviour**, registered per AGENTS.md §2.5 — this is what makes promotion to `main` safe.
- Agents **must not edit** user-dirty files: `TODO.md`, `README.md`, `BETA_SETUP.md`, `docs/field_mode_*.md`, `docs/classifier_routing.md`, `firmware/**`. Notes go in a new `docs/field_mode_progress/<stream>.md` per stream. I fold status into TODO.md/plan docs at the end, with the user.
- Each agent finishes with: green tests it ran (exact commands + counts), files touched, open issues, and any deviation from the plan doc with reason.
- Envs: Python `/Users/colincatlin/mambaforge/envs/minimappr/bin/python -m pytest tests/ --ignore=tests/test_soak_harness.py`; Rust `cargo test` (simulator built with `opt-level=3` in `[profile.test]`). Bluefin: user opens tunnel `ssh -i ~/.ssh/debian_192_168_1_180 -N -L 2222:localhost:22 -L 18080:localhost:8080 colin@192.168.8.103`, then `ssh -p 2222 colin@127.0.0.1` (repo `~/MinimapPR`, conda env `minimappr`, set `MAMBA_ROOT_PREFIX` for scp/rsync; box may suspend).

## Git & integration procedure

1. **Wave 0 (me):** create branch `field-mode` from `main`; commit only the field-mode docs (`docs/field_mode_*.md`) there so worktree agents can read them (user's other dirty files untouched).
2. Each agent runs with `isolation: "worktree"` on branch `fm/<stream>` off current `field-mode`, commits there.
3. End of wave (me): merge each `fm/*` into `field-mode`, resolve conflicts (expected hotspots: `config.py`, `config_groups.py`, `pipeline_graph.py`, `settings_store.py`, `fusion_node.py`, workspace `Cargo.toml`), run full pytest + `cargo test --workspace` (+ Bluefin for BirdNET), then start the next wave from the updated branch.
4. **Promotion to main:** for each stream that is self-contained and green, launch an **Opus reviewer agent** (`model: "opus"`, worktree) given the stream's diff (`git diff main...fm/<stream>`), AGENTS.md and the relevant plan section — not my conclusions — told to find correctness bugs and AGENTS.md violations and **fix them** on the branch. Re-run tests, then `git merge` into `main` from the main tree. Git refuses if a merge touches the user's dirty files; if that happens, stop and ask. No pushes.

## Verification

- Per wave: full `pytest` (minus soak) and `cargo test --workspace` green on `field-mode`; Bluefin pytest for BirdNET streams; `cargo build` for wasm32/android/ios targets; frontend `trunk build`.
- Server-track gate on simulated bundles rendered by `minimappr-sim render-bundle` (fixed seeds, committed expectations files) through `tests/test_calibration_replay.py`.
- Layer 2: 10 fixed seeds per PR under 5 s; nightly 200 seeds script.
- Phase 1 pre-study report gives a recommended chirp band/waveform/slot to test on real phones.
- Each promoted stream: Opus reviewer pass, tests re-run, then merged to `main`.

## Risks / notes

- Front-loading chirp-specific code before Phase 1 risks rework if phone chirps fail; mitigated because ranging/clock/layout math is waveform-agnostic (audible-chirp or clap fallback reuses it), and the sim pre-study narrows Phase 1.
- Sim-only gates can overfit the simulator; Bluefin snippets are the reality check, and real golden bundles still come in Phase 3.
- Hot-file merge conflicts in config/pipeline files — resolved by me at each wave boundary; agents add keys in contiguous, labelled blocks.
- Bluefin availability (tunnel, suspend) gates W1-birdnet-v3, W1-fixtures (snippet part) and W3-birdnet-cutover; if down, those agents do local parts and report.
